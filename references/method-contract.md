# 方法契约：从计算事实到两级模型图

## 1. 冻结依据

记录当前模型名、最终配置和证据来源位置。先确认模型版本，再分析算法。

来源的角色不同：代码显示实际执行，配置决定激活分支，论文表达作者意图，旧图保留已接受的视觉表达。冲突需显式解决，不能自行改实现或偷偷选一个版本。

每次只补充完成图稿所需的上下文，不扫描无关私有目录。

## 2. 最小计算清单

| 对象 | 记录内容 |
|---|---|
| 输入 | 来源/时点、dtype、形状、轴语义、缺失值或编码状态（仅当影响读图） |
| 表征 | ID、形状、所属分支、是数据还是参数 |
| 运算 | 实际公式/函数、输入端口、输出端口、轴和广播规则 |
| 输出 | 任务名、预测对象、形状、logit/概率/类别/变换后的连续值 |
| 边 | 数据流、参数/控制流、训练监督；是否经过变换 |
| 模块 | 输入输出接口、内部组件、是否共享权重、推理/训练作用域 |

例如 `[B,2]` 可以表示二分类的两个 logits，并不自动表示两个任务。两个特征时点的路线也不能因为都是二分类，就合成同一个预测。

回归若学习 `log(1+y)`，图中应把输出称为变换后的预测；只有实际做了逆变换才能直接标为原单位。不要把“估计总时长”误写为“估计延迟天数”。

## 3. 两级图的接口

### 模型总览

- 呈现从输入到各个最终输出的完整骨架。
- 展示与方法主张有关的核心模块，而不是用一个“神经网络”框遮住全部机制。
- 多路输入按照数据来源或可用时点区分；真实融合时才汇合。
- 模块边界标关键维度。其余公式可放细节图。
- 模块 ID 表示计算机制；重复 ID 不等于共享参数。需要时明确“独立实例”或“权重共享”。

### 核心算法图

- 使用总览相同的模块 ID、名称和颜色。
- 局部边界输入/输出与总览一致；细节可以增加中间张量，不能改变接口。
- 核心模块多于一张可读版面时先压缩重复内容；必要时说明如何分面板，而非无意生成互不对应的多版模型。
- 训练损失通过监督边连接，不伪装成推理时数据必经节点。

### 边界检查

逐一检查：总览中的模块能否在细节图定位；细节图的输出返回哪个总览端口；分支在两图是否一致；未展开的普通层是否有准确标签。

## 4. 模块与贡献

区分三个层面：

1. **实现组件**：层、统计量、损失、门控、投影等。
2. **方法模块**：多个组件共同完成的一项机制，也可以是单个关键算子。
3. **研究贡献**：相对于已有工作的可论证差异，需要文献与实验/理论支持。

不要强行规定“每个模块都是首创”“每个创新点必须包含多个组件”或“任何模型必须有三个创新点”。

用户要求按创新点重组时，先提供以下映射：

| 候选模块 | 内部组件 | 要解决的问题 | 特有机制 | 最近工作 | 当前证据状态 |
|---|---|---|---|---|---|

保留跨模块依赖。若表征模块同时服务加性与交互路径，应画出分叉，不能因叙述顺序把计算改成串行。

## 5. 命名

- 先明确计算对象、调节信号与操作，再给中文名、英文全称和短缩写。
- 名称可以体现“分位条件”“成员分歧”“形状对齐”“残差调控”等真实机制；不要凭命名增加“因果”“贝叶斯”“最优”“校准”“安全保证”等未经实现或验证的性质。
- 不把成员方差直接当作已校准的认知不确定性。可以称“成员分歧代理”，除非已有证据支持更强解释。
- 名称唯一性检索与机制新颖性检索分开。未发现同名不代表机制首创；缩写也可能跨领域重名。
- 研究创新尚未核实时，标注“候选机制/待核验贡献”。不要把图框大小或复杂度当创新证据。

## 6. 公式优先于故事

用实际公式检查单调性与解释，例如：

`w = sigmoid(a - b*s), b > 0; z = w*z_A + (1-w)*z_B`

随 `s` 增大，A 的权重下降、B 的权重上升。即使旧文字说“更信任 A”，也不能沿用错误叙述。指出冲突，不擅自改代码。

只有加性分支满足单变量可加性时，不能把整个含交互模型称为全局加性可解释模型。零初始化只说明初始状态，不构成训练后性能不下降的保证。
