# 专属绘图 Prompt 库

把 `{...}` 替换为实际信息。未知内容可写“以代码为准”或使用符号；不要把模板示例当作事实。

## A. 完整模型绘图

```text
使用 $research-model-diagrams。

以 {最终模型名称、代码/配置/方法文档} 为依据，绘制一张模型总览图和一张核心算法组件图。我之后会手工在 PPT 中重画。

要求：
1. 总览图展示真实输入、核心算法模块、各条路线及其各自的最终输出；不同任务不得误合并。
2. 核心算法按实际机制和候选创新点组织，不强行凑固定数量的模块。模块名、编号、颜色与总览一致，形成总览—细节层级。
3. 输入输出及关键中间表示要看出数据格式、张量形状和维度变化，同时画出矩阵网格、特征列、token 或张量堆叠。
4. 将真实存在的特征选择和特征提取流程可视化，例如 mask、索引、基函数曲线、特征贡献；没有选择器就不要添加。
5. 连线体现实际数学逻辑，在运算节点区分逐元素相加、矩阵乘法、逐元素乘法、拼接和标量缩放；注明广播和操作轴，并给出图例。
6. 不同局部参考相关论文的具体图。列出模块、论文、图号、可以借鉴的画法、如何改成我的方法。先核验图号，不能直接照搬。
7. 保留已经正确的表达，更新同一份规范图稿；不要同时给多种无法分辨的最终版本。
8. 不改模型实现，不编造维度、训练信号、实验曲线或创新结论。

先核对计算拓扑，再绘图并检查实际渲染。交付当前两张图、可用的编辑源，以及简短参考映射。
```

## B. 定向打磨，避免回退

```text
使用 $research-model-diagrams，继续修改 {现有图稿/源文件}。
本次只解决：{具体问题}。
必须保留：{已经正确的数据形态、维度、模块、分支、运算符等}。
不要把图形退回纯文字框，不要更改模型拓扑，不生成新的竞争版本。
完成后检查本次改动有没有造成其他正确内容丢失。
```

## C. 两张图建立层级

```text
总览图和组件图目前缺乏对应关系。请根据实际模型建立模块映射：总览显示模块与各自输出，组件图展开同名模块。
保持模型计算不变，检查每个细节面板的输入输出能否映射到总览端口。
保留数据可视化、维度变化和数学运算符，不将不同任务误合并。
```

## D. 只提供论文参考

```text
不修改图片。我会手工画 PPT，请针对 {模块/现有图} 给出参考论文。
每条必须包含论文标题、直达链接、已核验版本与图号、借鉴的局部表达，以及改成我的模型时的具体替换方式。
不要仅列论文题目，不要将参考论文中的额外机制画进我的模型。
```

## E. 只解释或组合模块

```text
不对图片和模型代码进行修改。
根据 {实际方法/代码} 解释 {输出作用/模块关系/公式含义}。
如果按研究问题和候选创新点组织，现有组件怎样组合成论文模块？请说明输入输出、跨模块依赖和训练/推理作用域。
不要因为组件数量少就否定创新，也不要因组合了多个组件就直接认定独创。
```

## F. 创新核验与学术命名

```text
不修改图片。请核验 {候选模块组合} 的已有研究，优先阅读最接近论文的方法与公式。
分别说明已有机制、当前方法的实质差异、还缺什么证据。
然后给出与实际机制一致的中文名、英文全称和缩写；名称查重与机制创新性核验分开。
未检索到完全相同的名称或组合，不应表述为全球首创。
```
