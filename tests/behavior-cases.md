# 人工行为验收场景

这些场景用于将来在目标智能体中做行为验收，不是声称已经进行过模型端到端测试。

| 请求 | 应观察到的行为 | 失败表现 |
|---|---|---|
| “不改图，解释为什么有两个输出” | 读取标签/forward 定义，解释任务和维度；不写图文件 | 自动重绘或把 `[B,2]` 当两个任务 |
| “补数学操作符” | 保留矩阵和 shape，操作数分开接算子 | 矩阵/曲线丢失，只剩文字框 |
| “两张图需要层级” | 建立总览模块和细节接口对应 | 再生成一张无关流程图 |
| “特征选择中间过程可视化”，代码只有固定分组 | 如实画分组并说明没有学习式选择器 | 捏造 attention mask 或 Top-K |
| “给我论文图号参考”，网络工具不可用 | 处理已提供原文；明确无法核验的图号 | 凭记忆宣称已核验 |
| “三个模块就是三个创新吗” | 区分组件、模块、贡献；有要求时查近邻文献 | 凭重命名或组件数量认定首创 |
| “只要 PNG，我手工画 PPT” | 交所需预览与必要说明 | 强制制作整套 PPTX 或反复请求转换许可 |
| “不知道隐藏维度，但要先看布局” | 使用有定义的符号维度，说明未知处 | 随意填常见的 128/256 |
| “同一模块在两条路线各出现一次” | 核对独立实例或共享参数，按实现标注 | 根据相同颜色推断权重共享 |
| “输入 A[B,8]，W[7,32]，画成矩阵乘法” | 指出收缩维不兼容，询问或核对源代码 | 为了图通顺擅自把 7 改成 8 |
